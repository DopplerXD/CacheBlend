# Evidence Token Coverage 对第三章的贡献

## 放置位置

这组实验更适合放在第三章，用作“基于语义相似度选择重算 Token”的合理性说明。它不是最终参数选择实验，也不用于确定某一个固定重算比例，而是从 Top-K ratio 的完整区间 `[0, 1]` 观察不同选择策略对答案证据 token 的覆盖趋势。

第三章可将其放在方法设计之后，作为一个轻量验证小节：

> 为验证基于查询语义相似度的 token 选择是否具有合理性，本文构造答案字符串弱证据区，并统计不同选择策略在不同 Top-K ratio 下对答案证据 token 的覆盖情况。

## 实验含义

实验将答案字符串及其邻域 token 视为弱证据区，然后比较以下策略在不同选择预算下的覆盖效果：

- `random`：随机选择 token，用作无语义基线。
- `chunk_head`：选择上下文开头 token，用作位置偏置基线。
- `embedding_max`：候选 token 与查询 token 的最大语义相似度。
- `embedding_mean_query`：候选 token 与查询平均向量的语义相似度。
- `embedding_last_query`：候选 token 与查询末尾 token 的语义相似度。

这个实验不能证明“语义相似度一定选中所有关键 token”，但可以检验一个较弱、也更适合本科论文的命题：**语义相似度选择出的 token 是否更容易覆盖答案相关证据区**。

## 数据有效性

| 数据集 | 扫描样本数 | 有效样本数 | 有效比例 | 有效样本是否截断 | 说明 |
|---|---:|---:|---:|---|---|
| musique | 100 | 64 | 64% | 全部截断到 4096 token | 可作为主分析数据 |
| wikimqa | 100 | 48 | 48% | 全部截断到 4096 token | 可作为主分析数据 |
| samsum | 100 | 0 | 0% | 无有效样本 | 摘要任务不适合该证据定义 |

需要在论文中说明：本实验是固定 4096 token 分析预算下的弱监督验证。由于长上下文样本被截断，结论应表述为“在受限上下文预算下的证据覆盖趋势”，不应表述为完整原始上下文上的严格结论。

`samsum` 是摘要任务，目标答案通常是整段摘要，而不是上下文中可直接匹配的原文字符串。因此用“答案字符串及邻域”定义证据区时无法得到有效样本。第三章中可以简单说明该任务不纳入 evidence coverage 分析即可。

## 全区间结果解读

### Evidence Recall

Evidence Recall 衡量被选择 token 对答案弱证据区的覆盖比例。从 `[0, 1]` 全区间曲线看：

- `wikimqa` 上，`embedding_max` 的全区间覆盖面积为 0.5832，高于 `random` 的 0.5033，说明查询语义相似度相比随机选择具有更强的答案证据覆盖倾向。
- `musique` 上，`embedding_max` 的全区间覆盖面积为 0.5048，与 `random` 的 0.4995 接近，说明语义相似度在该数据集上没有形成明显 recall 优势，但仍能保持接近随机基线的覆盖水平。
- `chunk_head` 在两个数据集上 recall 均较高，说明当前数据和截断方式存在位置偏置：部分答案证据集中在保留上下文的靠前区域。

适合写入第三章的结论不是“语义相似度全面优于所有方法”，而是：

> 语义相似度选择能够在不同重算预算下稳定覆盖答案相关 token，尤其在 WikiMQA 上表现出优于随机选择的证据覆盖趋势；同时，位置基线的较高结果说明数据中存在上下文位置偏置，因此本文将该实验作为语义选择合理性的弱监督支撑，而非严格证明。

### Evidence Hit

Evidence Hit 衡量一次选择是否至少命中部分答案证据。这个指标适合解释“是否保留了答案线索”，比 recall 更适合作为第三章的直观支撑。

从全区间趋势看，embedding 类方法在 `musique` 和 `wikimqa` 上都能较稳定地命中答案证据区。特别是在低预算区间，`embedding_max` 的 hit 趋势明显强于 `chunk_head`，说明语义相似度不是只依赖位置，而是能够跨样本找到与查询相关的答案线索。

第三章可以这样使用：

> 在较小选择预算下，基于语义相似度的方法虽然未必覆盖完整证据区，但更容易在不同样本中命中至少一部分答案证据。这与本文希望通过查询相关性保留关键上下文线索的设计目标一致。

## 对第三章的贡献

### 1. 为“语义相似度选择重算 Token”提供经验支撑

第三章提出的核心直觉是：与用户查询语义更接近的 token 更可能影响后续回答，因此应优先重算。该实验用答案字符串弱证据区验证了这个直觉的一部分：在 QA 数据集中，语义相似度选择出的 token 能够稳定覆盖答案相关证据。

可写表述：

> 从弱监督证据覆盖结果看，基于查询语义相似度的 token 选择策略能够在不同预算下持续覆盖答案相关区域，说明语义相似度可以作为查询感知重算的低成本代理信号。

### 2. 解释为什么选择 embedding similarity 而不是复杂特征

该实验只依赖 tokenizer、embedding 和答案字符串匹配，不需要完整生成流程。它说明即使使用较轻量的 embedding similarity，也能观察到一定的答案证据覆盖能力。

可写表述：

> 相比引入额外模型或复杂特征，embedding similarity 可直接由语言模型输入嵌入得到，计算代价较低，并在弱证据覆盖实验中体现出一定有效性，因此适合作为本文选择性重算策略的核心打分依据。

### 3. 区分“命中答案线索”和“完整覆盖证据”

Evidence Hit 和 Evidence Recall 可以帮助第三章把方法目标讲清楚：

- Evidence Hit 支撑“语义选择能保留答案线索”。
- Evidence Recall 支撑“随着预算增加，语义选择对证据区的覆盖逐步提高”。

这比只展示最终生成结果更适合第三章，因为第三章强调的是方法设计合理性，而不是最终性能对比。

### 4. 诚实说明方法边界

`chunk_head` 的 recall 较高，说明在部分数据中位置偏置很强。第三章可以把这一点写成局限性：

> 当答案证据集中在上下文前部时，简单位置策略也可能获得较高覆盖率。因此，语义相似度选择并非在所有数据分布下都严格优于位置基线，但它提供了与查询内容相关的选择依据，能够降低单纯位置选择的偶然性。

这样写比回避 `chunk_head` 更稳，也更符合实验结果。

作用：展示 Top-K ratio 从 `[0, 1]` 变化时，不同方法的 evidence recall 曲线。

## 第三章可直接使用的段落

为验证基于查询语义相似度选择重算 token 的合理性，本文构造了答案字符串弱证据覆盖实验。具体而言，在 `musique` 和 `wikimqa` 中，将答案字符串及其邻域 token 视为答案相关证据区，并统计不同 token 选择策略在 Top-K ratio 从 `[0, 1]` 变化时对证据区的覆盖情况。该实验不用于确定具体重算比例，而用于观察不同选择预算下的整体趋势。

实验结果表明，基于语义相似度的 `embedding_max` 方法能够在不同预算下持续覆盖答案相关 token。在 `wikimqa` 上，`embedding_max` 的 evidence recall 全区间覆盖面积高于随机选择，说明查询语义信息能够帮助选择器更有效地覆盖答案证据。在 `musique` 上，`embedding_max` 与随机选择接近，说明该数据集上语义相似度的覆盖优势不明显，但仍能保持稳定的证据覆盖能力。

此外，`chunk_head` 在 evidence recall 上表现较强，说明当前数据和截断设置下存在一定上下文位置偏置。因此，本文不将该实验解释为语义相似度方法对所有基线的严格优势，而是将其作为方法设计的弱监督支撑：语义相似度能够作为一种低成本的查询相关性代理信号，用于指导选择性重算优先保留与答案相关的上下文 token。

对于 `samsum`，由于其任务目标是生成摘要，参考答案通常不是上下文中的连续原文片段，无法通过答案字符串及邻域构造可靠证据区，因此该数据集不纳入本实验结论。

## 写作边界

- 可以写“语义相似度能作为低成本查询相关性代理信号”。
- 可以写“在 WikiMQA 上，语义相似度选择比随机选择具有更强的证据覆盖趋势”。
- 可以写“MuSiQue 上优势不明显，但覆盖能力稳定”。
- 可以写“位置偏置基线较强，说明数据结构会影响覆盖结果”。
- 不要写“语义相似度严格保证选中关键 token”。
- 不要写“embedding 方法全面优于 chunk_head”。
- 不要把 `samsum` 写入 evidence coverage 主结论。
- 不要在第三章用该实验确定具体重算比例。
